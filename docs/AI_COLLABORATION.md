## 2026-11-16 · 输出溢出与双轨对齐同题比较

两家收到相同的缓冲代码和验收条件，各执行一次，无重试。任务是推导溢出帧数、找出确实存在的播放问题并给出确定性测试。

| Worker 与模型 | 耗时与用量 | 有效发现与取舍 |
| --- | --- | --- |
| OpenCode Go `opencode-go/deepseek-v4.1-flash` | 77.5 秒。输入 2,660，输出 955，推理 5,706，缓存读取 0。 | 找到超长批次双轨各自截尾导致错位的复现，并给出帧数守恒关系和边界表。关于重缓冲不会重新武装的疑虑，经现有状态切换和测试排除。 |
| Command Code GOAT `deepseek/deepseek-v4.1-flash` | 38.7 秒。输入 14,760，输出 4,818，缓存读取 4,096。 | 独立找出同一错位，给出与 OpenCode 一致的溢出计数。停止时清零的建议未采用，保留最近一次计数供用户停止后导出。 |

采纳共同帧窗口和 `max(0, 未读帧 + 新增共同帧 - 容量)`。界面和诊断只增加本轮可验证的输出溢出丢弃帧，避免把已消费帧、源切换清空和不同长度的输入尾部混进该指标。供应商字段口径不同，耗时是本次实测。

旧代码上的斜坡数据复现双轨错位。自动化测试覆盖错位修复、一般回绕、恰好满容量、超长批次、已消费帧、计数复位和导出。

下一轮将可独立验收的模块直接交给 Worker，要求提交完整的文本补丁、正常与异常路径和测试矩阵。由一位负责方案，另一位审查关键风险。同题调用留给模型评估，避免每个小改动都做两份相同的工作。Codex 集中在验收、整合和测试。
